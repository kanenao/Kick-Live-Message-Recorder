# 追っかけ録画（β版実験機能）

手動LIVE録画で選択時のみ、yt-dlpのHLSダウンローダーをFFmpegに指定し、入力オプション `-live_start_index 0` を使います。配信サーバーが公開しているHLSプレイリストの最古セグメントからの取得を試みます。Kickはyt-dlpの汎用 `--live-from-start` の対応サイトではなく、放送開始から全編が取得できる保証はありません。

- 通常の手動録画・自動録画・VODは従来の動作を維持します。
- 再接続時は通常録画とし、過去の区間を繰り返し取得しません。別ファイルに保存し、自動連結はしません。
- 初回ファイルは `_chase` を付けます。実映像の開始時刻が不明なので録画プロセス起動時刻を同期基準として保存しません。コメント付き動画の開始時刻はファイル終端からの推定となり、手動調整が必要な場合があります。過去コメントは自動取得しません。
- LIVE終了後に配信全編のVODが公開される場合は、既存の過去配信ダウンロードから取得できます。自動VOD補完（公開VODを別ファイル取得）も選択できます。完全結合は未実装です。
- Windows実機のKick LIVEで追っかけ範囲・接続継続・停止後の再生・コメント同期を確認するまで実験機能です。

参考: https://ffmpeg.org/ffmpeg-formats.html#hls-1 / https://github.com/yt-dlp/yt-dlp#video-selection

## 放送終了後のVOD補完
- 追っかけ録画を選択したうえで、自動取得を明示的にONにして開始する。デフォルトOFF。
- 終了確認による録画完了時だけ、同じ配信者・同じ配信開始時刻に一致する公開VODを検索する。手動停止・異常終了は対象外。
- 60秒間隔、最大6回、同時最大5件。候補なし・曖昧・取得制限は自動で別番組を選ばない。アプリ終了で検索停止。再起動復元は未実装。
- 既存のVODキューに渡す。元映像を上書きせず、VODを別ファイルに保存する。完全版かどうかの実測検証・過去コメント補完・結合は未実装。
- 非公式Web API（https://kick.com/api/v2/channels/{slug}/videos）を利用するため、仕様変更・アクセス制限で検索できない場合があります。

## 過去コメント補完
- 自動VOD補完と過去コメント補完の両方をONにした場合のみ、確認済みVODのコメントをJSONL・TXT・ASSで取得。既存の取得器を直列利用し、手動取得やASS再生成が終了するまで待つ。VOD映像の取得とは独立して進行し、失敗しても元データを保持。
- キューはメモリ上のみ。アプリ再起動復元、別起動間の重複取得防止、映像の自動結合は未実装。

## コメント動画の時刻同期
同一VOD IDには相対時刻を利用し、部分LIVE録画にVODログを使用する場合は絶対時刻から動画開始推定値を引く。別VOD IDは除外する。プレビューと本番生成で共通処理を使用。開始時刻推定の誤差は残るため、実機で確認し手動調整が必要な場合がある。

## 次期β版：VOD公開待ちの再起動復元
- 公開VOD検索の待機・確認中の状態をPC内に保存し、再起動時に最大5件を復元します。確認回数は引き継ぎ、開始から24時間または6回で終了。取消済み・取得一覧へ渡した項目は復元しません。
- 検索とダウンロードの引き渡し直前に待機履歴から除外します。引き渡し直前の異常終了では手動取得が必要な場合があります。ダウンロードそのものやコメント取得キューの再起動再開・動画結合は未実装。
- 自動補完では旧VODメタデータAPIにも動画ID・配信者・公開済み/非LIVE状態の明示確認を要求します。不明なら自動取得せず、手動取得の既存動作は変更しません。
