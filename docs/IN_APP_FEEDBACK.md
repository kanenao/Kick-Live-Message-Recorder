# アプリ内「不具合情報・機能要望」送信（開発中）

## 現状
β版の画面・Electron IPC・ローカル下書き保存まで実装しています。**受信用HTTPSサービスは未配備で、アプリ内送信はまだ無効です。**
現状の報告は「GitHubフォーム（代替）」から可能です。受付サーバーを配備するまで公開済み機能と表現しないでください。

## 受付API契約
- ビルド／実行環境変数 `KICK_FEEDBACK_ENDPOINT` は **HTTPS** の受付URL
- `POST` / `Content-Type: application/json`
- 例：`{"kind":"bug","title":"録画できない","description":"録画ボタンが反応しない","steps":"1. ...","edition":"beta","version":"1.0.1-beta.96"}`
- HTTP 2xx: `{"issueNumber":123}`（GitHub登録成功後にのみ返す）
- 失敗：4xx/5xx。通信タイムアウトは15秒
- メインプロセスが版とバージョンを付与し、クライアント側では入力上限チェック
- GitHubトークンをインストーラーやJS、ログに含めない

## サーバー側で必須の安全対策
1. GitHub Appまたは最小権限のトークンをサーバーのシークレットに設定
2. 入力の型・長さ・サイズをサーバー側でも再検査する
3. IPなどによるレート制限、スパム・Bot対策、重複送信防止
4. リポジトリ／付与ラベルの許可リスト化。投稿本文を未信頼入力として扱う
5. `kind` と `edition` に応じて「不具合情報」「機能要望」「β版」「製品版」「AI判定待ち」を割り当てる
6. 診断ログ、配信情報、Cookie、シークレットは自動取得しない
7. GitHub APIでIssue作成できたときだけ受付番号を返す
8. 公開Issueへの掲載同意をUIで取得する
9. 障害時の再試行・二重送信防止、監視・乱用対策を検証する
