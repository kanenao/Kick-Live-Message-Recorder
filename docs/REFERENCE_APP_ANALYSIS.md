# 参考アプリ調査・機能統合方針

ユーザー提供の3つのWindowsアプリを、実行せずにファイル構造・文字列・設定名・埋め込みコマンドから調査した。アプリの実際の画面操作や挙動を実機確認したものではないため、以下はバイナリから確認できた実装要素に基づく整理である。

## 1. KickLiveRecorder.exe

確認できた要素：
- yt-dlp と FFmpeg を同梱フォルダー binary から呼び出す構成
- ライブ録画、VODダウンロード、録画プロセスの標準出力/エラー監視
- 再接続回数・再試行間隔・配信タイムアウト
- ブラウザーCookieの利用設定
- 保存先、空き容量しきい値
- ファイル名・フォルダー名・映像ファイル名・映像フォルダー名のテンプレート
- FFmpegによる形式変換、元ファイル削除、ゴミ箱移動、変換オプション
- コメントのXML/SRT/ASS/JSON出力、ASS色分け、エモート削除
- ログ出力、ウィンドウ位置・サイズ・終了確認

取り入れる方針：
- 録画エンジンはUIから分離し、yt-dlp/FFmpegのプロセス監視を行う
- 再接続・タイムアウト・保存容量制限を設定可能にする
- ファイル名/フォルダー名テンプレートをプレビュー付きで設定できるようにする
- 変換は元ファイルを保持する設定を初期値にし、削除は明示的なオプションにする

## 2. KickChecker.exe

確認できた要素：
- Kick OAuth Client Credentialsでアクセストークンを取得
- /public/v1/channels を利用した配信状態の確認
- 監視間隔・アクセス待ち時間・HTTPエラー後の再起動設定
- 録画アプリを2つまで登録し、引数付きで起動する設定
- 配信検出チェック、通知チェック
- 配信開始/終了時刻、稼働時間、HTTPエラーの表示
- タスクトレイ、起動時最小化、ウィンドウ位置・サイズ記憶
- ログ出力、ルームURLのコピー、ブラウザーで開く機能

取り入れる方針：
- Kick公式APIを使った複数チャンネル定期監視
- 監視間隔を設定可能にし、配信開始をWindows通知で知らせる
- APIエラー時に監視を停止せず、次の周期で再試行する
- 後続段階でタスクトレイ常駐、起動時最小化、稼働ログを追加する

## 3. KickMessageRecorder.exe

確認できた要素：
- 配信のチャンネルID・配信ID・チャットルームID・配信開始時刻などの取得
- チャットイベントに含まれる投稿時刻・本文・送信者の解析
- エモート文字列の削除設定
- XML/SRT/ASS形式への出力
- ASS字幕の色分け、ユーザー識別情報と色の割当
- ファイル名・フォルダー名テンプレート、保存先設定
- Kick内部のPusher WebSocket接続と、非公開と考えられるサイト側API文字列

取り入れる方針：
- チャット本文・投稿者・タイムスタンプを録画タイムラインと同期
- JSONを正規保存形式とし、XML/SRT/ASSは後処理エクスポートとして生成
- エモート処理・ユーザー色分け・出力ON/OFFを設定可能にする
- Pusherやサイト内部APIへの依存は避け、Kick公式イベント/APIとその認証・Webhook要件を優先する

## 4. 統合アプリの構成案

1. 監視サービス：Kick APIでチャンネル状態を検知し、開始/終了イベントを生成
2. 録画サービス：yt-dlp/FFmpegを管理し、映像・音声をファイル保存
3. チャットサービス：公式に利用可能な方法でメッセージを取り込み、JSONに保存
4. 同期/エクスポート：配信開始時刻を基準に映像とコメントを整列し、XML/SRT/ASSを生成
5. ライブラリ：録画・コメント・ログ・メタデータをまとめて検索・再生

## 5. 安全・権利・安定性

- 利用規約、配信者の権利、プライバシー、保存期間・削除要請に対応する
- 公式APIで提供されないデータを取得できると表示しない
- Cookieや認証情報は平文ログに出さず、安全な保存方式を使う
- 元映像の削除は初期状態で無効にし、ユーザーが明示的に選択したときのみ実行する
- ネットワーク切断、容量不足、異常終了時にファイルを破損させにくい終了処理を行う
