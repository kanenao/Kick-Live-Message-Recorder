# β版・製品版のリリース運用方針

このプロジェクトは、将来的にβ版と製品版（安定版）を分離して配布する。

## 目的

- β版：新機能を早く取り込み、開発者・希望するテスターが先行検証するチャンネル
- 製品版：β版で検証を終え、重大な既知不具合がなく、安定性基準を満たした変更だけを配布するチャンネル

「不具合ゼロ」は保証できない。製品版は、既知の重大不具合がなく、定義したテストに合格し、残る既知の制限をリリースノートに明記した版とする。

## バージョンと配布チャンネル

| チャンネル | バージョン例 | 用途 |
| --- | --- | --- |
| β版 | `0.1.0-beta.51` | 新機能・修正の先行テスト |
| 製品版 | `1.0.0`、`1.0.1` | 安定性確認済みの一般配布 |

- β版のGitHub ReleasesはPre-releaseとして公開する。
- 製品版のGitHub Releasesは通常のLatest Releaseとして公開する。
- β版と製品版の更新確認先・更新チャンネルを分離し、製品版にβ版が自動配信されないようにする。
- 製品版の更新は製品版チャンネル内の修正版だけを対象とする。
- バージョン番号は、タグ、`package.json`、アプリ画面、インストーラー名、リリースノートを必ず一致させる。

## 開発と昇格の流れ

1. 機能開発は作業用ブランチで行い、β版開発ラインへ取り込む。
2. β版としてビルドし、GitHub Actionsの型チェック・ビルド・Windowsインストーラー作成を確認する。
3. 実際のWindows環境で主要機能と既存機能の回帰テストを行う。
4. リリース候補を固定し、重大な不具合が見つかった場合はβ版で修正して再検証する。
5. 合格した特定コミットだけを製品版ラインへ昇格する。β版の未検証機能を一括で製品版へ流し込まない。
6. 製品版のタグと通常Releaseを作成し、製品版ユーザーへ配布する。

## 製品版への昇格条件

### 必須チェック

- [ ] TypeScript型チェックと本番ビルドが成功
- [ ] Windows x64インストーラーの作成と新規インストール確認
- [ ] 既存バージョンからのアップデート確認
- [ ] アンインストール・再インストール後の設定／録画データの扱いを確認
- [ ] 配信検知・録画開始／停止・自動再接続の確認
- [ ] コメント受信・保存・時刻同期の確認
- [ ] コメント付き動画の生成とプレビューの確認
- [ ] 配信記事の生成・更新・保存・削除の確認
- [ ] Ollama未導入・モデル未導入・AI接続失敗時のエラー表示確認
- [ ] ネットワーク切断、API制限、配信終了、録画ファイル異常などの異常系確認
- [ ] 長時間録画および複数チャンネル運用の負荷確認
- [ ] 既知の重大不具合が残っていないことを確認
- [ ] リリースノートに既知の制限・注意事項を記載

CI成功だけでは製品版への昇格条件を満たしたことにしない。実機での確認結果も記録する。

## 不具合修正の取り込み

- 製品版で発生した不具合は、影響範囲を絞った修正を製品版側で検証する。
- その修正をβ版にも戻し、同じ不具合が再発しないようにする。
- β版だけにある未検証の新機能を、製品版へ自動的に取り込まない。
- データ形式や設定形式を変更する場合は、バックアップ・移行・旧版互換性を確認する。

## 自動更新とデータ保護

- β版と製品版の更新メタデータ／配信先を混在させない。
- 製品版ユーザーが明示的にβ版へ切り替えない限り、β版へ更新されないことをテストする。
- β版から製品版へ移る場合は、設定・保存済み記事・録画・コメントログを保護し、移行前バックアップと互換性を確認する。
- 更新失敗時にユーザーデータを消さない。アプリ本体の再インストールで録画データを削除しない設計とする。

## 現在の運用方針（β版のみ）

- 当面はβ版だけを開発・ビルド・配布する。
- 現在確認済みの公開基準：`v0.1.0-beta.50`
- β51の作業基準：`v0.1.0-beta.50` から作成した `feature/beta51-ai-article-live`
- 製品版の完成・公開時期は未定。製品版用ブランチ、製品版向けRelease、自動更新チャンネルはまだ作成・有効化しない。
- β版のGitHub Releasesは引き続きPre-releaseとして扱い、バージョンは `0.1.0-beta.N` 形式に限定する。
- GitHub Actionsのリリーステスト対象タグは `v*-beta*` のみとし、通常の製品版タグ（例：`v1.0.0`）ではβ版のリリーステスト／公開ジョブを起動しない。
- β版の公開用ブランチは `release/*-beta*` とし、β版以外のリリースブランチ名を対象にしない。
- 今後製品版へ移行する場合は、ユーザーの方針を改めて確認し、β版の検証結果を見てから別途設計・実装する。
- 既存の `main`、`release/*`、GitHub Actionsの公開条件は履歴を確認してから整理する。既存ブランチを確認なしに強制移動・削除・マージしない。
