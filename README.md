# Kick Live Message Recorder

Kick配信の映像・音声・コメントを録画・保存するWindowsデスクトップアプリです。24時間の配信監視、コメント付き動画の生成、映像・音声・コメントを組み合わせたAI配信記事に対応しています。

> **最新公開版：0.7.0-alpha.80（α版）**  
> **最新公開版のソース：`release/v0.7.0-alpha.80`（タグ付き）**  
> 最新α版のインストーラーは公開済みです。**mainブランチのアプリコードは旧β版の履歴的スナップショット**で、最新α版のソースはタグ `v0.7.0-alpha.80` を参照してください。製品版はまだ公開していません。

## Kick版の不具合自動検出・開発中の修正

- [日次のα版回帰テスト](.github/workflows/alpha-daily-regression.yml)を設定。**毎日03:40（日本時間）**に、GitHub Releasesの最新α版と、最新の開発α版PRを調べてテスト・型チェック・Electronビルドを実行します。
- 自動テストで不具合を検出した場合は、GitHub Actionsに失敗履歴を残し、重複しないGitHub Issueを起票します。**不具合のない製品版と誤認しないよう、コードの自動マージ・無検証のリリース公開は行いません。**
- [公開済み `0.6.0-alpha.78` の開発履歴（PR #16）](https://github.com/kanenao/Kick-Live-Message-Recorder/pull/16)では、コメント保存先のエラーがWebSocket受信処理を止める問題と、巨大JSONL全文読込による過剰なメモリ使用を修正しました。巨大ログ・破損行・ディスクへの書込失敗を回帰テストで再現しています。
- これらの修正を含むα版をGitHub Releasesで公開しました。次の開発版では引き続き不具合検出とα版リリースを継続します。

## 0.5.1-alpha.77（公開済み）での配信AI新聞のOllama復旧・記事保護

- Ollamaが記事本文を空または不完全に返した場合、取得済み配信情報・コメント・音声文字起こしに絞って1回だけ自動再試行します。画像を送らない再試行では、映像を見たと断定しません。
- 同じ録画から記事を再生成しても、以前の記事を上書きせず `_rev2` などの連番で別版として保存します。
- 過去配信記事にAI参照候補として抽出できたコメント件数を明示します。
- LIVEコメントの解析待ちキューを最大2,000件に拡大し、ローカルAIの処理が遅い場合のコメント欠落を軽減します。
- 自動テスト、型チェック、Windowsインストーラー、自動更新用ファイルの検証とPre-release公開に成功。

## 0.5.0-alpha.76（公開済み）での配信AI新聞強化

- 監視に登録していない配信者も録画ライブラリから選択して配信AI新聞を生成可能にしました。
- コメントログを放送単位で自動選択し、別番組のコメント混入を防ぎます。古いログは必要に応じて手動追加・除外できます。

- Visionモデルから映像要約が返らない場合も、利用可能な音声・コメントをもとに生成した本文は残し、未解析の理由を案内します。
- LIVE配信でコメントが12件未満でも初回約30秒でAI記事の更新を予約。連続更新は既存の設定間隔を守ります。
- 過去記事の再解析で配信時間が現在日時まで延びる不具合と、録画中に記事生成し不完全なファイルが残る問題を修正しました。
- GitHub Actionsによる放送別ログ選択・アーカイブ時間保持・LIVE更新・AI応答形式・記事削除のテスト、Windows版インストーラー、自動更新ファイル検証に成功しました。

## 0.4.1-alpha.74（公開済み）でのニコ生風ASSの自動調整

- 過去配信ASSと「コメント付き動画を生成」の両方に「速度・入り方を自動調整する」ON/OFFを追加。初期値ONです。
- 短文／長文と直近のコメント集中度から1件ごとに流れる速度と画面右端の進入距離を自動計算。後から来るコメントが前のコメントを追い越さないよう速度差も判定します。
- 行が埋まっている場合は最大約1.2秒入場をずらし、衝突できない場合は一部を省略。過密時の全コメント表示を保証するものではありません。
- OFFでは手動の横断時間・速度・行数・間隔を継続して利用可能。元のJSONL／TXT／録画動画／AI記事は変更しません。

## 0.4.0-alpha.73（公開済み）でのニコ生風ASS字幕調整

- 右側から流れるタイミング・行ごとのコメントの距離を計算し、混雑時は埋まった行へ無理に重ねないよう改善。

## 主な機能

### 配信監視・録画
- Kickチャンネルの登録と、通常チャンネル／録画専用チャンネルの管理
- バックグラウンドでの配信状態監視（設定可能・最短10秒間隔）
- Windowsログイン時の自動起動、通知領域常駐
- 配信開始通知と自動録画、一覧からの手動録画
- yt-dlp・FFmpegによる映像／音声の保存と自動結合
- 録画エラー時の自動再接続
- 録画中のKick公式プレーヤープレビュー
- Kick VODのURL指定ダウンロード

### コメント取得・保存
- Kickコメントのリアルタイム受信とアプリ内表示
- チャンネル別・配信日時別のJSONL保存（旧日別ファイルも引き続き閲覧可能）
- 投稿者名・本文・時刻・バッジ・エモート等の記録
- LIVEコメントの自動取得とVODコメント履歴の取得（JSONL・TXT・ASS字幕を出力）
- 通常チャンネル／録画専用チャンネルごとの自動取得設定

### ニコ生風コメント付き動画
- 録画動画とコメントログを合成してMP4を生成
- 白文字・太い黒フチ・影によるニコ生風表示
- 右から左へのスクロール、上部固定、下部固定、コメントごとの位置指定
- 長文・短文の移動速度調整と、同じ行でのコメント衝突回避
- ASS出力時にKick emoteを削除するON/OFF設定（プレビューと過去配信ASS出力にも対応）
- 実際のコメントログを使った生成前プレビュー
- フォント・文字サイズ・速度・行数・間隔・不透明度などの調整
- 元動画・元コメントログを変更せず、別ファイルとして出力

### AI配信記事
- 記事カードに16:9の放送画面を掲載。LIVE中は代表フレームを約25秒ごとに更新し、録画記事は動画から抽出した代表画像を表示（画像は必要なカードだけ遅延読み込み）。
- 録画済み配信とLIVE配信の記事生成・更新
- 映像の代表フレーム、音声文字起こし、視聴者コメントを分けて分析し、記事へ統合
- 新聞風の見出し・要約・本文・注目ポイントを生成
- LIVE中の記事を段階更新し、配信終了時に最終化
- LIVE映像解析の接続が予期せず終了した場合は、接続状態を判定して再取得。記事専用LIVEの音声FFmpegも映像とは独立して接続先URLを取り直し、自動再接続。音声の進捗停止も90秒で検出を試行
- 未登録チャンネルでもKick URL／チャンネル名から記事専用LIVEを開始可能
- Ollama（無料ローカルAI）とOpenAI APIに対応
- OllamaのVision／音声認識モデルの導入・進捗表示
- 記事の検索、日付別表示、LIVE速報／アーカイブ切替、個別削除

### アプリ更新
- 専用画面で現在のバージョン・更新確認・ダウンロード進捗を表示
- 起動時・定期的なアップデート確認（旧β版・α版の互換チャンネルを追加）
- Windowsインストーラー版のα版自動更新
- リリースノートと過去の更新履歴をアプリ内で確認

## 無料AI記事生成（Ollama）

1. [Ollama公式サイト](https://ollama.com/download)からWindows版をインストールします。
2. アプリの「配信記事」でAIエンジンを「Ollama（無料・ローカルAI）」に設定します。
3. Visionモデルは `qwen2.5vl:3b`、音声認識モデルは `frozenlab/qwen3-asr:0.6b` を利用できます。
4. アプリ内のモデル導入機能から必要なモデルをダウンロードし、接続テストを実行します。
5. LIVE記事を自動生成する場合は、LIVE自動記事化を有効にします。

初回のモデル取得にはインターネット接続が必要です。処理速度はPCのメモリ・CPU・GPU性能に依存します。ローカルOllamaを利用する場合、AI処理は設定したOllama環境で実行されます。OpenAI APIを選択した場合は、設定に応じて配信情報・コメント・代表フレーム・文字起こしテキストがAPIへ送信され、利用料が発生します。

## コメント付き動画の同期

VODコメントは保存された配信経過秒数、LIVEコメントは録画開始時刻とコメント時刻を基準に同期します。α51では、新しいLIVE録画のプロセス起動時刻を `RecordingMetadata/` に保存し、コメント付き動画の生成時に優先利用します。メタデータのない過去録画はファイル名・更新時刻による推定へフォールバックします。実配信での同期誤差測定は継続課題です。

## α版のリリース運用

今後はα版として開発・テストを進めます。α版の公開は `v*-alpha*` タグだけを使用し、β版タグ・通常の製品版タグではα版公開ジョブを実行しません。開発ブランチへの通常のpushは検証用ビルドであり、それだけで一般公開されません。α60のみ、明示的な公開依頼に対応する一回限りの公開ジョブで、テストとWindows成果物の検査後にタグとPre-releaseを作成します。以前の未公開開発番号β51・β52は、番号を保ったままα51・α52へ移行しました。過去に公開したβ50は公開履歴として残します。

### バージョン番号の決め方

バージョンは `MAJOR.MINOR.PATCH-alpha.N` 形式で管理します。最新公開α版は `0.4.2-alpha.75` です。ベース番号は開発状況に応じて更新し、`alpha.N` は連番を維持してリセットしません。

- **PATCH**：既存機能の不具合修正、安定性・性能改善、小規模な調整（次回例：`0.2.7-alpha.62`）。
- **MINOR**：互換性を保った主要機能の追加・拡張、開発上の大きな節目（次回例：`0.3.0-alpha.62`）。
- **MAJOR**：安定版公開後の大きな互換性変更。初回の `1.0.0` は製品版の安定性基準を満たした段階で判断し、番号だけを理由に早めない。

`alpha.N` は上記3つの数字とは独立したα版の開発連番です。開発を進めるたびに `52 → 53 → 54 → 55 → 56 → 57` と増やし、PATCH／MINOR／MAJORを更新しても連番をリセットしません。次回は内容に応じて `0.2.7-alpha.62` または `0.3.0-alpha.62` のように判断します。
