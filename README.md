# Kick Live Message Recorder

Kick配信の録画・コメント保存を行うWindowsデスクトップアプリです。

**開発版：0.1.0-beta.46**

## 主な機能

- Kickチャンネルの登録・削除
- 配信中／オフライン状態の確認と24時間バックグラウンド自動監視（通知領域常駐・Windowsログイン時の自動起動）
- LIVE中の配信者カード（通常チャンネル・録画専用チャンネルの表示名・プロフィール画像・配信タイトル・カテゴリ・開始時刻・経過時間・視聴者数）
- 配信開始時のWindows通知と自動録画・コメント自動接続（通常チャンネルと録画専用チャンネルを設定で対象化）
- チャンネル管理とは独立した「録画専用」一覧（手動録画）
- 通常チャンネル・録画専用チャンネルそれぞれのコメント自動取得ON／OFF
- 録画専用チャンネル一覧からのワンクリック映像録画＋コメント取得
- アプリ起動時・チャンネル追加時のKickチャット自動接続
- Kickコメントのリアルタイム受信・JSONL保存・画面表示
- yt-dlp・FFmpegをアプリに同梱し、m3u8（HLS）配信の映像・音声を自動結合して保存
- 録画ファイル一覧・再生・保存先表示・個別削除（削除前に確認し、録画中のファイルは削除不可）
- 保存済みLIVE／VODコメントJSONLをASS字幕に変換して動画へ焼き込む「コメント付き動画」生成（LIVEは同じチャンネルの複数日ログをまとめて指定可能）
- コメント付き動画のプレビューで、選択した実際のコメントログから本文・投稿者名・色を読み込み、動画内の有効コメント数・範囲外件数・破損行数を事前確認
- コメント付き動画の表示位置を中央スクロール・上部固定・下部固定から選択可能。固定表示はコメント表示時間と行の空き状況を使って重なりを防止し、長文コメントの横幅計算・縮小表示を改善
- 録画エラー時の自動再接続（回数・待ち時間を設定可能）
- 録画中チャンネルのライブ映像プレビュー（Kick公式埋め込みプレーヤー、設定でON／OFF可能）
- Kick過去配信（VOD）のURL指定ダウンロード
- Kick過去配信のコメント履歴ダウンロード（JSONL・TXT、配信経過時刻・ユーザー名・本文を保持）
- 登録配信者ごとの配信記事生成・保存（録画後の記事とLIVE中のリアルタイムAI記事）、記事検索・個別削除（LIVE更新中の記事は削除不可。元動画・コメントログは保持）
- 録画動画から最大8枚の代表フレームを抽出し、画像対応AIで映像の場面・画面表示を分析して記事へ反映（コメントログなしでも映像だけで生成可能）
- 登録配信者のLIVE記事でコメント・配信情報に加えて生放送の代表フレームを解析。未登録チャンネルもKick URL／名前を入力するだけで録画せず記事専用LIVEを開始可能
- 専用の「バージョン更新」画面（現在のバージョン・更新確認・ダウンロード進捗・再起動更新・リリースノート・過去の更新履歴）
- 起動時・定期的なアップデート確認

## バージョン更新

左メニューの「アプリ」→「バージョン更新」から、現在のバージョン、更新確認の状態、ダウンロード進捗、GitHub Releasesのリリースノート、過去の更新履歴を確認できます。「更新を確認」で手動確認し、新しい版が見つかるとバックグラウンドで自動ダウンロードします。ダウンロード完了後は「再起動して更新」から更新を適用できます。自動確認は起動時と約6時間ごとに行います。自動更新はWindowsインストーラー版が対象です。

## 配信記事

### 未登録チャンネルのLIVEを記事だけ生成（beta46）\n\n「配信記事」画面の「登録不要：LIVE記事だけ生成」にKickチャンネル名または `https://kick.com/チャンネル名` を入力して開始します。チャンネル管理・録画専用一覧への登録は不要で、映像録画ファイルも作成しません。Kick API認証を使って配信中か確認し、一時的にチャット受信先へ追加して記事を更新します。LIVE映像はyt-dlpで取得した配信URLをFFmpegで読み取り、25秒間隔で代表フレームを継続抽出し、AIへ渡す画像は直近8枚に制限します。記事の「記事を保存して終了」を押すと最終化し、一時的に追加したコメント受信先を元へ戻します。既存の自動受信チャンネルは維持します。\n\n登録不要の単発モードもKick API Client ID／Secretと、OllamaまたはOpenAIのAI設定が必要です。録画は行いませんが、コメントJSONLの保存は「コメントを保存する」設定に従います。Ollamaの映像解析はローカルモデルで行い、動画全体の保存はしません。\n\n### 録画映像から記事を生成（beta45）

記事一覧で配信者と録画動画を選び、「映像・コメントAI分析付き記事を生成」を押すと、録画動画から一定間隔で最大8枚の代表フレームを抽出し、AIが見える場面・画面内の表示内容を記事へ反映します。コメントログがない場合も、動画の映像分析だけで記事を生成できます。Ollama利用時は画像入力に対応するOllama 0.7.0以降とVisionモデルが必要です。推奨モデルは `qwen2.5vl:3b` で、初回は `ollama pull qwen2.5vl:3b` を実行してください。Qwen2.5-VL 3Bは画像入力に対応し、モデルサイズは約3.2GBです。映像フレームの抽出にはアプリ同梱のFFmpeg／FFprobeを使用し、JPEGをメモリへ読み込んだ後、一時ファイルはAI送信前に削除します。記事JSONには映像要約・時刻付き場面説明・使用フレーム数を保存します。

**映像解析の制約：** 動画全体を連続再生して理解する機能ではなく、一定間隔で抽出した静止画の分析です。音声・会話の内容やフレーム間の動きは認識しません。画像から確認できない出来事は推測しないよう指示しています。Ollama利用時はフレームをPC内のOllamaへ送ります。OpenAI API利用時は抽出した画像もAPIへ送信され、API利用料が発生します。手動の録画済み記事生成は「LIVE中のリアルタイムAI記事」のON／OFFとは独立しています。


記事一覧では見出し・配信者名・カテゴリ・キーワードで記事を検索できます。保存済み記事はカード下部の「この記事を削除」から個別削除できます。削除前に確認が表示され、削除されるのは記事JSONだけです。元動画とコメントログは保持されます。LIVE更新中・配信終了処理中の記事は誤削除防止のため削除できません。

### 無料AI（Ollama）のセットアップ

1. [Ollama公式サイト](https://ollama.com/download)からOllama 0.7.0以降のWindows版をインストールします（Qwen2.5-VLの画像入力に必要です）。
2. PowerShellで `ollama pull qwen2.5vl:3b` を実行してモデルを取得します。
3. Ollamaを起動した状態でアプリの「配信記事」を開き、AIエンジンを「Ollama（無料・ローカルAI）」にします。
4. 接続URLは通常 `http://127.0.0.1:11434`、モデル名は `qwen2.5vl:3b` のまま「Ollama接続テスト」を実行します。
5. 接続成功後、「登録配信者のLIVEを自動でAI記事化する」をONにします。

モデルのダウンロードには初回のみ通信が必要です。モデル実行自体はPC内で行われ、APIキー・クラウドAIの従量課金は不要です。処理速度はPCのメモリ・CPU/GPUとモデルサイズに依存します。

beta32では、録画後の記事生成に加えてLIVE中のリアルタイムAI記事に対応しました。

左メニューの「配信記事」でAIエンジンに「Ollama（無料・ローカルAI）」を選ぶと、OpenAI APIキーなしで配信記事を生成できます。Ollamaをインストールしてモデル（初期値 `qwen2.5vl:3b`）を取得し、接続テストに成功したら「登録配信者のLIVEを自動でAI記事化する」をONにしてください。24時間監視がLIVEを検知したタイミングで記事を作成し、受信コメントを一定量ごとにまとめてローカルOllamaへ送り、タイトル・本文・話題・注目ポイントを更新します。従来のOpenAI APIも選択して利用できます。配信終了時には記事を最終化し、コメント数・投稿者数・視聴者数・最大視聴者数・配信時間を保存します。録画済み配信の記事も同じ設定がONなら、選択したコメントログをAI分析して記事本文を強化します。記事は `Articles/配信者名/` にJSONで保存されます。

Ollama利用時はコメント・配信情報をPC内の `http://127.0.0.1:11434` へ送り、外部AIサービスへ送信しません。OllamaのモデルはPCのメモリ・CPU/GPUを使用します。OpenAI APIを選択した場合は、APIキーをWindowsのElectron `safeStorage` で暗号化し、通常の設定ファイルや画面へ平文保存しません。OpenAI利用時はコメント本文・配信者名・配信タイトル・カテゴリ・視聴者数などをOpenAI APIへ送信し、API利用料が発生します。AIモデルと更新間隔（30秒～10分）を選択できます。AIを有効にすると、通常のコメント自動取得設定がOFFでも、登録した通常・録画専用チャンネルのコメントを記事生成用に受信します。

**分析対象の制約：** 現在のAI記事はKickの配信タイトル・カテゴリ・視聴者数・公開チャットコメントを分析します。配信映像・音声そのものを直接視聴・認識した要約ではありません。コメントから確認できない発言や出来事は推測しないよう指示し、コメント本文に含まれる命令文も指示として扱わない設計です。従来の録画動画を選んで作る記事生成も引き続き利用できます。

## 24時間バックグラウンド監視

beta29以降は配信監視をElectronメインプロセスで実行します。アプリのウィンドウを閉じても通知領域へ常駐し、最短10秒間隔で登録チャンネルのLIVE状態を確認します。配信開始を検知すると、通常チャンネルは「自動録画」モードの設定に従って録画を開始します。録画専用チャンネルの自動録画設定は通常チャンネルとは独立しており、こちらだけを自動録画ONにすることもできます。チャット自動取得が有効なチャンネルはコメントもJSONLへ保存します。起動直後にすでにLIVE中のチャンネルも検出対象です。

Windowsログイン時の自動起動を有効にすると、サインイン後に通知領域でバックグラウンド起動します。監視中のスリープ抑止設定も用意しています。有効時はWindowsのスリープとディスプレイ消灯を抑止するため、画面は点灯したままになります。画面右上の×はアプリ終了ではなく通知領域へ隠す操作です。完全終了は通知領域アイコンを右クリックして「アプリを終了」を選択してください。

**監視の制約：** Windowsがシャットダウン中、ユーザー未ログインで自動起動が未実行、ネットワーク切断、Kick APIの障害・アクセス制限中は監視できません。PCの電源を切る・休止状態にする・ノートPCのふたを閉じる設定によっては監視が止まります。10秒監視はAPIの応答遅延やアクセス制限がない場合の目安であり、配信開始と同時の検知を保証するものではありません。コメント受信はKickの非公式リアルタイム接続に依存し、再接続中のコメントは取得できない場合があります。

## コメント付き動画の生成

左メニューの「コメント付き動画」から、録画ライブラリの動画と `Chat/チャンネル名/` に保存されたJSONLコメントファイルを選択します。日付をまたいだLIVE配信は、同じチャンネルの対象日ログを複数選択できます（最大31ファイル）。異なるチャンネルのログやLIVEとVODの混在はできません。LIVEコメントは録画ファイル名に含まれる録画開始時刻を優先して同期し、名前を変更した動画などは更新時刻と再生時間から開始時刻を推定します。LIVEログが日付ごとに分割されている場合は、同じチャンネルの複数ファイルを選択してまとめて使用できます。VODコメントは取得時に保存した配信開始からの経過秒数を使って同期します。同期ずれは秒単位で調整できます。

設定画面内の「コメント表示プレビュー」を強化し、設定を変更した瞬間にプレビューを再描画してコメントのアニメーションを先頭から再生します。フォント・文字サイズ・速度・画面横断時間・不透明度・最大行数・コメント間隔・投稿者名表示が即時反映され、現在の設定値もプレビュー上部に表示します。同じ行を使うサンプルコメントも用意し、間隔設定の変化を確認できます。表示行数は1080p相当で画面内に収まる数へ制限します。プレビューはサンプルコメントによる見た目の確認用で、実際の行配置・重なり判定・コメント数は選択した動画とログに基づいて生成時に決定します。\n\nコメントは参考動画のように、太字・黒縁取りで右から左へ流します。標準フォントはメイリオ、文字サイズ48、表示12行です。フォントはＭＳ Ｐゴシック・メイリオ・游ゴシック・Arialから選べ、文字サイズ・画面横断時間・流れる速度（50〜200%）・最大表示行数・コメント同士の最小間隔・不透明度・投稿者名表示を調整できます。コメントの縦位置は上下の余白を除く画面全体の高さへ均等に分散させ、上部の同じ行へ偏らないようにします。動画の高さと文字サイズから実際に表示できる行数を自動で制限します。同じ行を使う場合は、先行コメントの移動速度・経過時間と新しいコメント自身の文字幅から間隔を計算し、速度差による追い越しも考慮して重なりを防ぎます。動画の終端付近でもコメントが急に速くならないようにしています。表示可能な行がない場合は省略件数に計上します。動画とコメントを合成したMP4は `CommentVideos/` に保存し、元動画・元コメントは変更しません。エンコード画質は高画質・標準・容量優先から選択できます。HandBrake本体を起動するのではなく、アプリに同梱したFFmpegで処理します。

## 録画中の映像プレビュー

録画中のチャンネルがある場合、ダッシュボードと「録画専用」画面の上部にKick公式プレーヤーを表示します。設定画面の「配信プレビュー」で表示をON／OFFできます。OFFにしても録画・コメント取得には影響しません。複数チャンネルを同時録画している場合は、プレビューするチャンネルを切り替えられます。プレビューはミュート状態で自動再生を試みます。ブラウザーの自動再生制限やKick側の配信状態・埋め込み制限により、再生ボタンの操作が必要な場合があります。プレビューは視聴用で、録画処理・コメント受信とは独立しています。

## 過去配信（VOD）のダウンロード

「録画専用」画面の「過去の配信（VOD）を録画」に、KickのVideosページからコピーした `https://kick.com/チャンネル/videos/動画ID` のURLを貼り付けてダウンロードします。yt-dlpとFFmpegを使用し、動画ファイルとして録画ライブラリの保存先へ保存します。対象は公開状態で取得可能なVODです。チャンネル名とURL内のチャンネル名が一致することを検証します。同じURL入力欄から「過去配信のコメントを取得」を実行すると、VODの開始時刻・配信時間に合わせてKickのコメント履歴をページ取得し、`Chat/チャンネル名/` にJSONLとTXTで保存します。ライブコメントの受信とは別処理です。

## 録画方法

### チャンネル管理

1. ダッシュボードでKickチャンネルを登録します。
2. 自動モードなら配信開始を検知して自動録画します。手動モードなら一覧から「録画開始」を押します。
3. 設定画面の「Kickチャットを自動取得」がONなら、アプリ起動時やチャンネル追加時にコメントへ自動接続します。

### 録画専用

1. 左メニューの「録画専用」を開きます。
2. 録画したいKickチャンネル名またはURLを登録します。
3. 配信中に「録画開始」を押します。
4. チャンネル行の「録画＋コメント取得」を押すと、映像録画とコメント受信を同時に開始します。コメント自動接続も有効になり、次回起動後も自動接続します。上の設定をOFFにすると、次回起動時の自動接続を止められます。録画停止後もコメント受信は設定に従って継続します。

録画とコメント付き動画の生成には yt-dlp・FFmpeg・ffprobe を使用します。Windows版インストーラーには3つを同梱するため、別途インストールやPATH設定は不要です。HLS（m3u8）配信の映像・音声もFFmpegで自動処理します。FFmpegのライセンス文書とビルド情報はアプリのresources/tools内に同梱しています。

通信切断などで録画プロセスが異常終了した場合は、設定画面の「録画の自動再接続」で指定した回数・待ち時間に従って再接続します。初期値は5回・10秒です。手動停止または配信の正常終了では再接続しません。再接続後の録画は元のファイルを上書きしないよう、`_retry02` などの連番付きファイルとして保存します。

録画専用一覧は、配信状態の自動監視・配信開始時の自動録画には含まれません。コメント自動取得は通常チャンネルとは別にON／OFFできます。

## コメント受信

通常のチャンネル管理と録画専用の両方で、コメント自動取得を個別に設定できます。受信したコメントは画面に表示し、チャット保存が有効なら `Chat/チャンネル名/YYYY-MM-DD.jsonl` に保存します。同時接続は合計50チャンネルまでです。

ngrok、Cloudflare Tunnel、独自ドメイン、Webhook URL登録、コメント受信用の追加トークンは不要です。

### コメント受信方式について

コメント受信はKickのWebサイトが利用するリアルタイム接続（Centrifugo）と内部エンドポイントに依存します。Kickの公式公開Webhook/APIではありません。Kick側の仕様変更、アクセス制限、接続方法の変更により、一時的または恒久的に動作しなくなる可能性があります。公式APIと同等の安定性は保証するものではありません。

## Kick API接続設定

Kick公式APIを使った配信状態の自動監視には、Kick Developerで作成したアプリのClient IDとClient Secretが必要です。Client SecretはWindowsの暗号化機能で保護して保存されます。チャットの直接受信だけならClient ID／Client Secretは不要です。

## 開発環境

- Node.js 22以上
- Windows 10/11（デスクトップアプリ）
- Electron、React、TypeScript、Vite

```bash
npm install
npm run dev
```

```bash
npm run dist:win
```

## データ保存

- チャンネル一覧・録画専用一覧・設定：Electronのユーザーデータ領域
- 録画映像・音声：設定画面で指定したフォルダー
- チャット：`Chat/チャンネル名/YYYY-MM-DD.jsonl`
- Client Secret：WindowsのElectron safeStorageで暗号化して保存

## 利用上の注意

録画・チャット保存はKickの利用規約、配信者の権利、プライバシー、適用法令を守って利用してください。配信者の許可を得たうえで利用し、保存したデータを適切に管理してください。
