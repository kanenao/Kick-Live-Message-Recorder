# Kick Live Message Recorder

Kick配信の映像・音声・コメントを録画・保存するWindowsデスクトップアプリです。24時間の配信監視、コメント付き動画の生成、映像・音声・コメントを組み合わせたAI配信記事に対応しています。

> **最新公開版：0.1.0-beta.50**  
> **開発中：0.1.2-alpha.54（未公開）**  
> 現在の開発・テスト対象はα版です。過去に公開したβ版は履歴として保持し、製品版は未完成のため公開・自動更新していません。

## 主な機能

### 配信監視・録画
- Kickチャンネルの登録と、通常チャンネル／録画専用チャンネルの管理
- バックグラウンドでの配信状態監視（設定可能・最短10秒間隔）
- Windowsログイン時の自動起動、通知領域常駐
- 配信開始通知と自動録画、一覧からの手動録画
- yt-dlp・FFmpegによる映像／音声の保存と自動結合
- 録画エラー時の自動再接続
- 録画中のKick公式プレーヤープレビュー
- Kick VODのURL指定ダウンロード

### コメント取得・保存
- Kickコメントのリアルタイム受信とアプリ内表示
- チャンネル別・日付別のJSONL保存
- 投稿者名・本文・時刻・バッジ・エモート等の記録
- LIVEコメントの自動取得とVODコメント履歴の取得（JSONL・TXT・ASS字幕を出力）
- 通常チャンネル／録画専用チャンネルごとの自動取得設定

### ニコ生風コメント付き動画
- 録画動画とコメントログを合成してMP4を生成
- 白文字・太い黒フチ・影によるニコ生風表示
- 右から左へのスクロール、上部固定、下部固定、コメントごとの位置指定
- 長文・短文の移動速度調整と、同じ行でのコメント衝突回避
- 実際のコメントログを使った生成前プレビュー
- フォント・文字サイズ・速度・行数・間隔・不透明度などの調整
- 元動画・元コメントログを変更せず、別ファイルとして出力

### AI配信記事
- 記事カードに16:9の放送画面を掲載。LIVE中は代表フレームを約25秒ごとに更新し、録画記事は動画から抽出した代表画像を表示（画像は必要なカードだけ遅延読み込み）。
- 録画済み配信とLIVE配信の記事生成・更新
- 映像の代表フレーム、音声文字起こし、視聴者コメントを分けて分析し、記事へ統合
- 新聞風の見出し・要約・本文・注目ポイントを生成
- LIVE中の記事を段階更新し、配信終了時に最終化
- LIVE映像解析の接続が予期せず終了した場合は、接続状態を判定して再取得。登録チャンネルはバックグラウンド監視で、記事専用LIVEは段階的な待機時間で再接続を試行
- 未登録チャンネルでもKick URL／チャンネル名から記事専用LIVEを開始可能
- Ollama（無料ローカルAI）とOpenAI APIに対応
- OllamaのVision／音声認識モデルの導入・進捗表示
- 記事の検索、日付別表示、LIVE速報／アーカイブ切替、個別削除

### アプリ更新
- 専用画面で現在のバージョン・更新確認・ダウンロード進捗を表示
- 起動時・定期的なアップデート確認
- Windowsインストーラー版のα版自動更新
- リリースノートと過去の更新履歴をアプリ内で確認

## 無料AI記事生成（Ollama）

1. [Ollama公式サイト](https://ollama.com/download)からWindows版をインストールします。
2. アプリの「配信記事」でAIエンジンを「Ollama（無料・ローカルAI）」に設定します。
3. Visionモデルは `qwen2.5vl:3b`、音声認識モデルは `frozenlab/qwen3-asr:0.6b` を利用できます。
4. アプリ内のモデル導入機能から必要なモデルをダウンロードし、接続テストを実行します。
5. LIVE記事を自動生成する場合は、LIVE自動記事化を有効にします。

初回のモデル取得にはインターネット接続が必要です。処理速度はPCのメモリ・CPU・GPU性能に依存します。ローカルOllamaを利用する場合、AI処理は設定したOllama環境で実行されます。OpenAI APIを選択した場合は、設定に応じて配信情報・コメント・代表フレーム・文字起こしテキストがAPIへ送信され、利用料が発生します。

## コメント付き動画の同期

VODコメントは保存された配信経過秒数、LIVEコメントは録画開始時刻とコメント時刻を基準に同期します。α51では、新しいLIVE録画のプロセス起動時刻を `RecordingMetadata/` に保存し、コメント付き動画の生成時に優先利用します。メタデータのない過去録画はファイル名・更新時刻による推定へフォールバックします。実配信での同期誤差測定は継続課題です。

## データ保存

- 録画映像・音声：設定した録画保存先
- コメント：`Chat/チャンネル名/YYYY-MM-DD.jsonl`
- AI記事：`Articles/チャンネル名/`
- コメント付き動画：`CommentVideos/`
- LIVE録画の同期情報（α51から保存）：`RecordingMetadata/`

Client SecretはWindowsのElectron `safeStorage` で暗号化して保存します。

## α版のリリース運用

今後はα版として開発・テストを進めます。α版の公開は `v*-alpha*` タグだけを使用し、β版タグ・通常の製品版タグではα版公開ジョブを実行しません。開発ブランチへのpushは検証用ビルドであり、それだけで一般公開されません。以前の未公開開発番号β51・β52は、番号を保ったままα51・α52へ移行しました。過去に公開したβ50は公開履歴として残します。

### バージョン番号の決め方

バージョンは `MAJOR.MINOR.PATCH-alpha.N` 形式で管理します。現在の `0.1.0-alpha.52` はそのまま維持し、今後は機能・修正の規模と互換性への影響を見て `MAJOR.MINOR.PATCH` を更新します。

- **PATCH（例：0.1.1）**：既存機能の不具合修正、安定性・性能改善、小規模な調整。
- **MINOR（例：0.2.0）**：互換性を保った大きな機能追加、主要機能の拡張、開発上の節目となる改善。
- **MAJOR（例：1.0.0以降）**：安定版公開後の大きな互換性変更。初回の `1.0.0` は製品版の安定性基準を満たした段階で判断し、番号だけを理由に早めない。

`alpha.N` は上記3つの数字とは独立したα版の開発連番です。開発を1回進めるごとに `52 → 53 → 54` と増やし、PATCH／MINOR／MAJORを更新しても連番をリセットしません。たとえば次回が小規模修正なら `0.1.1-alpha.53`、主要機能追加なら `0.2.0-alpha.53` のように、内容に応じて3つの数字を判断します。

## コメント取得方式について

コメント取得はKickのWebサイトが利用するCentrifugoリアルタイム接続と内部エンドポイントに依存します。Kickの公式公開Webhook/APIではありません。Kick側の仕様変更・アクセス制限により動作しなくなる可能性があり、公式APIと同等の安定性は保証しません。

## 利用上の注意

録画・コメント保存はKickの利用規約、配信者の権利、プライバシー、適用法令を守って利用してください。配信者の許可を得たうえで利用し、保存したデータを適切に管理してください。
