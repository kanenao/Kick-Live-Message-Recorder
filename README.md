# Kick Live Message Recorder

Kick配信の映像・音声・コメントを録画・保存するWindowsデスクトップアプリです。24時間の配信監視、コメント付き動画の生成、映像・音声・コメントを組み合わせたAI配信記事に対応しています。

> **最新公開版：0.8.0-alpha.86（α版）**  
> **次期α版：0.8.1-alpha.87（録画ライブラリのサムネイル・保存先の安全性改善をテスト中）**  
> 現在の開発・テスト対象はα版です。過去に公開したβ版は履歴として保持し、製品版は未完成のため公開・自動更新していません。

## 0.8.0-alpha.86 LIVE配信AI新聞の映像全時間帯サンプリング（公開済み）

- LIVE映像のAI解析用フレームを直近8枚だけに限定せず、配信全体から均等に選ぶリザーバー方式へ変更。過去の代表フレーム最大7枚と最新フレームを合わせて最大8枚を保持します。
- FFmpegの一時切断後に再接続しても、同じ配信セッションの代表フレーム履歴を維持。メモリに保持するJPEGは最大8枚です。
- 記事画面ではAIに実際に送った代表フレーム数と、キャプチャした累計枚数を分けて表示します。
- AIの一時的な接続障害では最終解析を最大2回再試行。未解析コメントと文字起こし済み音声区間は記事データへ保存し、アプリ再起動後も記事の再解析操作から復旧できます。
- 記事画面に未解析のコメント件数・音声区間数を表示。録画動画がある場合は再解析時に映像と音声を再取得し、Vision解析もやり直します。
- 元動画・録画・コメントJSONL・ASSは変更しません。記事JSONにはAI解析結果と未解析キューの状態を保存し、既存の録画・チャットファイルは変更・削除しません。抽出・再接続・復旧を自動テストします。

## 0.7.2-alpha.82 録画ライブラリの配信者別フォルダー化（公開済み）

**今後新しく録画するLIVE・過去配信は、自動的に配信者IDごとへ保存します。** 同じ配信者が表示名を変えても、フォルダーを別人として分断しないようKickのチャンネルID（slug）を使用します。

```text
Kick Live Message Recorder/
├── Recordings/
│   ├── daibututv2/    ← LIVE・過去配信の録画動画
│   └── otherchannel/
├── Chat/
│   ├── daibututv2/    ← コメントJSONL（従来どおり）
│   └── otherchannel/
├── CommentVideos/
│   ├── daibututv2/    ← コメント付き生成動画・ASS字幕
│   └── otherchannel/
├── RecordingMetadata/ ← LIVE録画時刻の対応情報
└── RecordingSessions/ ← 番組ごとの録画記録
```

- 録画ライブラリは**新しい配信者別フォルダーと、以前の直下保存・旧CommentVideos保存の両方**を表示し、配信者別にまとめます。
- 配信者カードには保存先の場所と「保存先を開く」ボタンを追加。クリックするとその配信者の動画／コメントの保存先をエクスプローラーで開きます。
- **過去の録画・ASS・コメント・AI記事を自動移動・改名・削除しません。** AI記事の元動画パスが変わってリンク切れになるのを防ぐためです。
- フォルダー名の入力検証、リンク型フォルダーの拒否、旧録画互換、安全な削除の回帰テストを追加します。

- 記事の根拠一覧はAIによる創作ではなく取得済みの情報源を参照します。映像フレームの一覧は、そのフレームをAIが理解できたことを保証しません。

## 主な機能

### 配信監視・録画
- Kickチャンネルの登録と、通常チャンネル／録画専用チャンネルの管理
- バックグラウンドでの配信状態監視（設定可能・最短10秒間隔）
- Windowsログイン時の自動起動、通知領域常駐
- 配信開始通知と自動録画、一覧からの手動録画

- 録画中のKick公式プレーヤープレビュー

### コメント取得・保存
- Kickコメントのリアルタイム受信とアプリ内表示
- チャンネル別・配信日時別のJSONL保存（旧日付単位ファイルも読み込み可能）

- LIVEコメントの自動取得とVODコメント履歴の取得（JSONL・TXT・ASS字幕を出力）

- フォント・文字サイズ・速度・行数・間隔・不透明度などの調整
- 元動画・元コメントログを変更せず、別ファイルとして出力

- 録画済み配信とLIVE配信の記事生成・更新
- 映像の代表フレーム、音声文字起こし、視聴者コメントを分けて分析し、記事へ統合
- 新聞風の見出し・要約・本文・注目ポイントを生成
- LIVE中の記事を段階更新し、配信終了時に最終化
- LIVE映像解析の接続が予期せず終了した場合は、接続状態を判定して再取得。記事専用LIVEの音声FFmpegも映像とは独立して接続先URLを取り直し、自動再接続。音声の進捗停止も90秒で検出を試行
- 未登録チャンネルでもKick URL／チャンネル名から記事専用LIVEを開始可能
- Ollama（無料ローカルAI）とOpenAI APIに対応
- OllamaのVision／音声認識モデルの導入・進捗表示
- 記事の検索、日付別表示、LIVE速報／アーカイブ切替、個別削除

## α版のリリース運用

今後はα版として開発・テストを進めます。α版の公開は `v*-alpha*` タグだけを使用し、β版タグ・通常の製品版タグではα版公開ジョブを実行しません。開発ブランチへの通常のpushは検証用ビルドであり、それだけで一般公開されません。α60のみ、明示的な公開依頼に対応する一回限りの公開ジョブで、テストとWindows成果物の検査後にタグとPre-releaseを作成します。以前の未公開開発番号β51・β52は、番号を保ったままα51・α52へ移行しました。過去に公開したβ50は公開履歴として残します。

### バージョン番号の決め方

バージョンは `MAJOR.MINOR.PATCH-alpha.N` 形式で管理します。現在の開発版は `0.2.7-alpha.62` です。今回のPATCH更新は、α版の自動更新チャンネル修正です。

- **PATCH**：既存機能の不具合修正、安定性・性能改善、小規模な調整（次回例：`0.2.7-alpha.62`）。
- **MINOR**：互換性を保った主要機能の追加・拡張、開発上の大きな節目（次回例：`0.3.0-alpha.62`）。
- **MAJOR**：安定版公開後の大きな互換性変更。初回の `1.0.0` は製品版の安定性基準を満たした段階で判断し、番号だけを理由に早めない。

`alpha.N` は上記3つの数字とは独立したα版の開発連番です。開発を進めるたびに `52 → 53 → 54 → 55 → 56 → 57` と増やし、PATCH／MINOR／MAJORを更新しても連番をリセットしません。次回は内容に応じて `0.2.7-alpha.62` または `0.3.0-alpha.62` のように判断します。
